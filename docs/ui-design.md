# UI設計

ITに詳しくない人が、説明を読まずに使えることを優先する。

## 共通

- 1列の画面にし、上から「撮る・選ぶ → 応募先ごとの一覧 → コピー」の順に並べる。PCでも幅を広げすぎない（最大 `2xl`）。
- タップ領域は44px以上、入力欄の文字は16px以上にする（iPhoneの自動ズームを防ぐため）。
- シリアルは等幅の書体で、字間を少し空けて出す。0とO、1とIを見分けやすくするため。
- アイコンは線のSVG（`components/Icon.tsx`）を使い、UIの飾りに絵文字を使わない。
- ボタンは `components/Button.tsx` を使い、色と大きさは `variant`・`size` で選ぶ。className には位置だけを渡す。
- 色は semantic token（`bg`・`surface`・`text`・`accent`・`warn`・`danger`・`done`）を使う。端末が暗いテーマなら暗い色になる。
- 動きは `prefers-reduced-motion` で止める。

## 画面

| 画面 | 内容 |
| --- | --- |
| 読み取り（`#`） | 端末の外へ送らないことの説明、「カメラで撮る」「写真を選ぶ」、準備・読み取りの進み具合、応募先が分からないシリアル、応募先ごとの一覧、ブックマークレットへの入口、すべて削除。 |
| ブックマークレット（`#bookmarklet`） | ブックマークレットとは、登録のしかた（PC・iPhone・Android）、使い方、登録失敗への注意、プログラムの中身。 |

- 応募先の一覧は、シリアルごとに写真の切り抜きを並べる。注意のあるシリアルは行の地を `warn.soft` にし、理由を書く。
- 10件ずつのコピーボタンは2列に並べ、コピー済みは色を落として ✓ を出す。

## 言葉づかい

- 「シリアル」「応募先」「応募サイト」「読み取り」「コピー」「ブックマークレット」を使う。
- 確定のボタンは、作るときは「追加する」「作る」、直すときは「保存する」、消すときは「削除する」。やめるときは「やめる」。
- 削除の確認は、何が消えるかと「元に戻せません。」を書く。
- 読み取りの結果は「N枚の写真からN件のシリアルを読み取りました。」。すでに読み取ったシリアルは件数を知らせて除く。1件も見つからず重複もないときだけ撮り直しを促す。
- 失敗は、何ができなかったかと次にすること（通信を確かめる、開き直す）を書く。
