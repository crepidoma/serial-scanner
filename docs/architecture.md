# アーキテクチャ

## 構成

```
写真 ─ 画面（src/client）
        │ createImageBitmap → canvas で画素にする（長い辺4000px・検出用に1920px）
        ▼
      Web Worker（src/ocr/worker.ts）
        │ core.ts  文字の検出（DBNet）→ 傾きを直して切り出し → 文字の認識（CTC）
        │ parse.ts シリアル・タイトル・URLを見分け、シリアルごとに応募先の手がかりを付ける
        ▼
      画面 ─ store.ts で応募先にまとめ、localStorage に保存
```

| 場所 | 役割 |
| --- | --- |
| `src/client` | React の画面。状態は `lib/store.ts`（`useSyncExternalStore`）。 |
| `src/ocr` | 読み取りのWorker。`core.ts`・`parse.ts` はNode.jsからも動かす（`scripts/eval-ocr.ts`）。 |
| `src/shared` | 画面とWorkerで使う型、タイトル・アーティストの比較。 |
| `src/bookmarklet` | ブックマークレットの元のコード。`scripts/vite-bookmarklet.ts` が圧縮して `virtual:bookmarklet` として画面に渡す。 |
| `src/assets/models` | PaddleOCR（PP-OCRv4）の検出・認識モデルと文字の一覧。 |

## 読み取り

PaddleOCR の PP-OCRv4 を onnxruntime-web（WASM）で動かす。OpenCV を使わず、必要な幾何計算（凸包・最小外接長方形・回転した切り出し）を `core.ts` に書いている。OpenCV.js は数MB増えるため。

- **向き**: 検出した行は長い辺を読む向きにし、まず読む。確信度が0.9未満なら180°回して読み直し、高い方を使う。逆さまの行は確信度がほぼ0になるため見分けられる。
- **速さ**: 説明文の細かい行まで読むと時間の大半をそこに使う。行の高さが中央値の1.2倍以上の行（シリアル・タイトル・URL）だけを先に読み、シリアルが1件も見つからなかったときだけ残りも読む。
- **シリアル**: 英大文字と数字だけの10〜20文字の行。
- **タイトル**: シリアルの「上」（紙の向きで見た上）にある、文字の大きい数行のまとまりの1行目。上から順に、すぐ下に大きな行が続いている行を選ぶ。上に重なった別の紙の注意書きのような、1行だけ離れた行を拾わないため。
- **アーティスト**: 紙に印刷された `ticket.fortunemeets.app/<アーティスト>/` の部分。末尾の「/」まで読めたものだけを使い、応募先ごとに多数決で決める（重なった紙ではURLが途中で切れる・読み違えるため）。
- **同じ応募先か**: タイトルの似ている度合い（レーベンシュタイン距離、または短い方を長い方の一部と比べた値）が0.75以上で、含まれる数字の並びが一方に含まれ、アーティストも似ていること。「42nd」と「40th」は文字列としては似ているため、数字で分ける。

### 試した結果（2026年10月）

実物の紙の写真6枚（1枚・45°傾き・逆さま・4枚・4枚バラバラ・10枚でシングル3種類が混在）で、写っているシリアル19件をすべて正しく読み、応募先も正しく分けた。処理時間は紙10枚の写真でNode.jsが約2秒、Chromium（WASM・1スレッド）が約11秒、WebKitが約15秒。

## 配布物とキャッシュ

- `vite build` で静的ファイルを出力する。`base: "./"` で相対パスにし、GitHub Pagesのようにパスの途中に置かれても動かす。
- 初回に約30MB（WASM 14MB・認識モデル 11MB・検出モデル 5MB）を取得する。画面を開くとWorkerが取得を始め、進み具合を出す。
- `scripts/vite-service-worker.ts` が全ファイルの一覧を埋め込んだ `sw.js` を出力する。画面は通信を優先し、ほかのファイル（ハッシュ付き）はキャッシュを優先する。版が変わっても、同じファイル（モデルなど）は前のキャッシュから引き継ぐ。
- モデルの取得はService Workerがページを制御し始めてから行う（`main.tsx`）。先に取得すると、その通信がキャッシュに入らないため。

## 制約と判断

- **1スレッドで動かす**: 複数スレッドには COOP/COEP のヘッダーが要り、GitHub Pagesでは付けられない。Cloudflare Pagesでは付けられるが、onnxruntime-web の1ファイルにまとめた版をWorkerの中で複数スレッドにすると準備が終わらなかったため、今は使わない。
- **写真のデコードは画面側**: Workerで画像を扱う `OffscreenCanvas` が使えないブラウザがあるため。iPhoneのSafariはcanvasの画素数に上限（約1,670万）があり、長い辺を4000pxに縮める。
- **React 19 と `javascript:` URL**: React 19 は `href` に `javascript:` を渡すと無効にするため、ブックマークレットのリンクは ref でDOMに直接設定する。
- **CSP**: `index.html` の meta で `connect-src 'self'` などを指定する。WASMの実行に `'wasm-unsafe-eval'` が要る。
